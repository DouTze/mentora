# 逐區塊導讀：設計

2026-10-06。取代「一個主題一次寫完整段導讀」的做法。

## 為什麼

一次導讀的範圍（主題）改成「一個完整主題」之後，段落變大，導讀變得很不穩定。原因不在模型讀不下輸入，在於：

1. **輸出太長**。4B 模型一次要寫出整段的翻譯、命題、導讀與逐項稽核，容易漏句、陷入重複（伺服器以 token repeat limit 中止）或撞到輸出上限被截斷。
2. **失敗連鎖**。檢查是「每個命題都要過」；主題越大，命題越多，整段通過的機率以乘法下降。一項沒過就整段修訂，修訂時又曾把原本寫好的內容刪掉。
3. **英文的長度上限形同虛設**。上限以 token 計，5,000 字母的英文段落只算約 1,250 tokens，後面卻要產出完整的中文翻譯、命題與導讀。

做法：學生看到的仍是一個完整主題；模型內部只處理**一個區塊**（約一個自然段）。主題長度不再轉嫁到任何一次模型呼叫。

## 詞彙

| 詞 | 意思 | 程式 |
| --- | --- | --- |
| 主題 | 一次導讀的範圍 | unit／quote |
| 區塊 | 主題內約一個自然段的原文 | `quote["chunks"][k]` |
| 來源區塊 | 抽取時的最小單位（中文 PDF 約一句） | `SourceBlock` |
| 命題 | 一句話層級的主張 | claim（C1…） |
| 區塊摘要 | 一個區塊的「大主題｜面向」與一句內容摘要 | `chunk.topic／aspect／summary` |
| 主題總摘要 | 由區塊摘要寫成的整個主題概要 | `guide["topic_summary"]` |

## 流程

```text
來源區塊 ──組成──▶ 區塊 ──逐批──▶ 區塊摘要 ──逐批──▶ 主題範圍
                                                       │
                       主題總摘要＋本段重點＋讀完想一想 ◀┘
                                                       │
           每個區塊：原文＋區塊摘要＋主題脈絡 ──▶ 導讀子流程（命題、撰寫、檢查、核對、修訂）
                                                       │
                              原文區塊 1 → 導讀 1 → 原文區塊 2 → 導讀 2 …（同一頁）
```

### 1. 組成區塊（程式）

`segmentation.make_chunks`：依來源區塊的段落標記，一個自然段一個區塊；標題併入它下面的第一段；不可切開的關係（「因此…」「其中…」、程式碼與說明）不跨區塊。過長的段落在句子之間切開（上限 `CHUNK_MAX_CHARS`），過短的區塊併入相鄰區塊（`CHUNK_MIN_CHARS`）。

### 2. 區塊摘要（模型，`segment_outline`）

每批最多 `OUTLINE_BATCH` 個區塊，為每個區塊寫：

- `topic`：大主題（總覽寫「…總覽」；同一項目的說明、限制、例子沿用同一個大主題）
- `aspect`：講這個大主題的哪一面
- `summary`：一句話內容摘要

- `role`：需不需要導讀。`content`（教學內容，不確定時一律是它）、`toc`（目錄）、`summary`（重複正文的摘要或重點回顧）、`other`（版權頁、參考文獻、索引等）。

數量必須與區塊相同。無效時重試一次，再無效就以原文開頭代替摘要並記錄。

**不需要導讀的區塊**（units-v10）：`role` 不是 `content` 的區塊，以及程式從形狀判定為目錄的區塊（至少三行、多數以頁碼結尾），不進入任何主題，也不做主題判斷。程式碼、公式與表格不會只因模型的判斷被略過。全部區塊都被判為不需導讀時一律保留。略過的內容記在 `segmentation.skipped`（性質、位置、原文），第一個主題的頁面上可展開查看，匯出也會列出，判斷錯了看得出來。

### 3. 主題範圍（模型，`segment_topic`）

只看區塊摘要，回答新大主題從第幾個區塊開始（沿用單題檢查第二步的提示詞）。區塊摘要逐批送出，每批最後一個主題可能延續到下一批，所以放回下一批重新判斷；一批裡看不到換主題時，下一批從這批的最後一個區塊開始，讓緊接著的轉換仍能被指出。判斷無效時，改在「大主題」寫法改變處切開。

**主題範圍只由語意決定**，沒有任何依長度合併或拆開主題的規則：導讀一次只處理一個區塊，主題多長都不會轉嫁到模型的單次呼叫。小標題不強制切開主題；模型判斷小標題底下仍是同一個大主題時，就留在同一段導讀。長度規則只在區塊層級（`CHUNK_MAX_CHARS`、`CHUNK_MIN_CHARS`），決定模型每次處理多少原文。

### 4. 主題總摘要（模型，`reading_topic`）

輸入主題內的區塊摘要，輸出：主題總摘要、本段重點（1–3 點）、讀完想一想（一個問句）。只有一個區塊的主題不呼叫，重點與問句取自該區塊的導讀。

### 5. 逐區塊導讀（既有導讀子流程）

每個區塊各跑一次原本的導讀子流程（公式取證、命題與中文課文、Gate 1、教學補充、撰寫、程式檢查、稽核、核對、修訂），輸入只換成該區塊的原文與來源區塊。撰寫、修訂與教學補充的提示詞多一段「主題脈絡」：主題總摘要、本區塊摘要、前後區塊摘要。提示詞明確要求：

- 內容一律以本區塊原文為準；摘要只用來判斷這一塊講到哪裡、怎麼承接，不是內容來源；
- 不寫後面區塊的內容。

檢查仍拿導讀比對原文與命題，**不比對摘要**，摘要寫錯也不會讓錯的導讀通過。

每個區塊有自己的預算、自己的重試。沒通過的區塊**自動重新產生**（新的嘗試、新的操作鍵與預算，模型重新抽樣），連同第一次最多 `READING_BLOCK_ATTEMPTS` 次（預設 3，環境變數 `MENTOR_BLOCK_ATTEMPTS`）；重來也不會成功的原因（輸入超過模型上限、前後文讀不到、沒有能看圖的模型或沒有版面證據）不重試。每次失敗的原因留在紀錄（`failed_attempts`）。已通過的區塊依內容快取，重試時不會重寫。

### 6. 組成主題的導讀

- 全部區塊都沒通過：主題沒通過，照舊顯示原因與重試。
- 至少一個區塊通過：主題可閱讀。自動重試後仍沒通過的區塊只顯示原文與「這部分的導讀沒有通過檢查，可以先讀原文」，可單獨重試（`retry_blocks` 事件，只重做沒通過的區塊）。學生可以繼續往下讀。
- 命題（筆記與出題的依據）只取通過的區塊，重新編號為主題內唯一的 C1、C2…。

## 資料格式

`quote["chunks"]`：

```json
[{"block_ids": ["…"], "text": "區塊原文", "topic": "規則式方法", "aspect": "代表技術", "summary": "ELIZA 與專家系統…"}]
```

`reading.guides[idx]`（逐區塊時）：

```json
{"mode": "blocks", "topic_summary": "…", "key_points": ["…"], "check": "…", "partial": false,
 "blocks": [{"index": 0, "block_ids": ["…"], "source": "區塊原文", "summary": "…", "status": "accepted",
             "guide": "…", "chinese_text": null, "unverified": [], "warnings": [], "claims": ["C1", "C2"],
             "error": null, "attempt": 1}],
 "guide": "各通過區塊導讀接起來（問答、匯出、筆記沿用）", "source_claims": ["重新編號後的命題"]}
```

舊的學習紀錄（沒有 `chunks`）照舊一段一次產生，前端照舊顯示。

## 相容

- 新的提示詞代號（`segment_outline`、`reading_topic`）在 session 的提示詞快照裡才走新流程；舊快照沿用原本的視窗規劃與整段導讀。
- 切段版本升為 units-v9，導讀流程版本隨之更新；進行中的舊 session 不受影響。

## 不做的事

- 不把各區塊導讀交給模型再潤飾成一篇：合併由程式做（逐塊顯示），避免已檢查的內容在合併時被改壞。
- 摘要不當內容來源，不核對摘要本身。
